## 진행 내용

### Windows 로그온 타입별 비밀번호 캐싱

Windows에서 사용자가 로그온하면 방식에 따라 LSASS라는 시스템 프로세스의 메모리에 비밀번호가 캐시될 수 있다. 공격자가 해당 호스트를 침해하면 이 메모리를 덤프해 캐시된 비밀번호를 탈취할 수 있으므로, 어떤 로그온 방식이 비밀번호를 남기는지 아는 것이 핵심이다.

| 로그온 타입 | 이름 | 설명 | 비밀번호 캐시 |
|---|---|---|---|
| 2 | Interactive | 콘솔에서 직접 로그인 | O |
| 3 | Network | 파일 공유(SMB) 등 네트워크 접근 | X (기본) |
| 4 | Batch | 예약 작업(Scheduled Task) 실행 | O |
| 5 | Service | Windows 서비스 시작 | O |
| 7 | Unlock | 화면 잠금 해제 | O |
| 8 | NetworkCleartext | IIS Basic Auth 등 평문 전송 | O |
| 9 | NewCredentials | RunAs /netonly | O (네트워크용) |
| 10 | RemoteInteractive | RDP 원격 데스크톱 | O |
| 11 | CachedInteractive | 도메인 컨트롤러 없이 캐시로 로그온 | O |

> Type 3(Network)은 기본적으로 비밀번호를 캐시하지 않지만, Kerberos Delegation이 설정된 환경에서는 예외가 존재한다.

### 핵심 이벤트 로그 구조 분석

이 도구가 파싱해야 하는 Windows Security 이벤트 로그의 핵심 Event ID는 다음과 같다.

#### Event ID 4624 — 로그온 성공

로그온 세션이 시작될 때 기록된다. 아래는 이벤트 뷰어에서 확인한 4624 이벤트의 상세 화면이다.

![이벤트 뷰어에서 확인한 Event ID 4624 상세 화면](/images/mogakco_16.png)

주요 필드:

| 필드명 | 설명 |
|--------|------|
| TargetUserName | 로그온한 계정명 |
| TargetDomainName | 도메인명 |
| TargetLogonId | 새로 생성된 세션의 고유 ID |
| LogonType | 로그온 방식 (위 표 참고) |
| IpAddress | 원격 로그온 시 접속 IP |

#### Event ID 4634 / 4647 — 로그오프

세션이 종료될 때 기록된다. 4634는 시스템이 자동 정리한 경우, 4647은 사용자가 직접 로그오프한 경우이다. TargetLogonId로 어떤 로그온 세션이 끝났는지 매칭할 수 있다.

#### Event ID 4672 — 관리자 권한 부여

로그온 시 관리자급 권한이 부여되면 기록된다. 이 이벤트가 있는 세션은 도메인 관리자 등 고위험 계정일 가능성이 높다.

### EVTX 파싱 테스트

`python-evtx` 라이브러리를 사용해 Security.evtx에서 로그온 성공(4624) 이벤트를 추출하는 기본 코드를 작성했다.

```python
import Evtx.Evtx as evtx
import xml.etree.ElementTree as ET

def parse_logon_events(evtx_path: str):
    with evtx.Evtx(evtx_path) as log:
        for record in log.records():
            root = ET.fromstring(record.xml())
            ns = {'ns': 'http://schemas.microsoft.com/win/2004/08/events/event'}

            event_id = root.find('.//ns:EventID', ns)
            if event_id is not None and event_id.text == '4624':
                data = {}
                for item in root.findall('.//ns:Data', ns):
                    data[item.attrib.get('Name', '')] = item.text

                print(f"[4624] {data.get('TargetDomainName')}\\{data.get('TargetUserName')} "
                      f"Type:{data.get('LogonType')} "
                      f"LogonId:{data.get('TargetLogonId')} "
                      f"IP:{data.get('IpAddress')}")
```

VM에서 수집한 Security.evtx로 테스트한 결과, 로그온 이벤트가 정상적으로 파싱되는 것을 확인했다.
